# 无 Docker 本地开发环境方案

> 基于 2026-11-10 13:26 在本机的实测结果。所有结论都来自实际探测（端口连通、HTTP 状态码、响应头、数据库查询），非估算。

## 0. 硬约束与选择

| 项 | 决策 |
| --- | --- |
| 容器 | **不使用 Docker**。`docker-compose-local.yml` 虽然可用（本机已装 Docker 29.7.2），但 Docker Desktop 守护进程不启动，且不作为本项目本地开发路径 |
| 平台 | Windows，PowerShell 5.1（`local-dev.ps1` 的 `#Requires`） |
| 一键入口 | [`local-dev.ps1`](../local-dev.ps1) / [`local-dev.cmd`](../local-dev.cmd) |
| 后端 Python | `uv`（必须 0.12.21，见 `apps/api/pyproject.toml` 的 `required-version`），设置在 `strata.settings.local_native` |
| 前端 | `pnpm` + turbo，web/admin/space 三个 react-router 应用 |

官方 Docker 栈（`docker-compose-local.yml`）会拉起 **7 个服务**：`strata-db` / `strata-redis` / `strata-mq` / `strata-minio` / `api` / `worker` / `beat-worker`（外加一次性 `migrator`）。本方案要在**没有 Docker** 的前提下，把这 7 个角色的差距补到"功能可用"。

## 1. 现状实测（2026-11-10 13:26）

运行中的进程与端口全部健康：

| 端口 | 服务 | 实测 |
| --- | --- | --- |
| 3000 | web（主应用） | HTTP 200，返回的是 Vite dev SSR HTML（含 `/@fs/…`、`/app/entry.client.tsx` 模块地址） |
| 3001 | admin（`/god-mode/`） | HTTP 200 |
| 3002 | space（`/spaces/`） | HTTP 200 |
| 8010 | Django API | `GET /api/instances/` 200，响应头带 `djdt-request-id`、`Server-Timing: TimerPanel_…`、`SQLPanel_…` |
| 55432 | 私有 PostgreSQL 集群（`.local\pgdata`） | 已就绪，`strata` 库存在 |

**确认是开发模式**，不是生产构建：

- 后端 `DEBUG=True`：`/api/instances/` 的响应头里有 Django Debug Toolbar 的面板计时；访问不存在的路径返回 Django HTML 调试页（生产会是 JSON）。
- 前端是 Vite dev server：HTML 里是未打包的模块地址，不是 `assets/*.js`；`web:dev` 日志有 `[vite] (ssr) connected` 与 HMR 注入。
- `apps/api/.env` 中 `DEBUG="1"`，`apps/web|admin|space/.env` 的 `VITE_API_BASE_URL="http://localhost:8010"`。
- 跨域/会话配置齐全：`CORS_ALLOW_CREDENTIALS=True`，`CORS_ALLOWED_ORIGINS` 与 `CSRF_TRUSTED_ORIGINS` 覆盖 3000/3001/3002/3100，`SESSION_COOKIE_SAMESITE=Lax`（同站不同端口，登录态可正常保持）。

数据库里已有真实数据，**实例不是全新的**：

```
users: 2
  guanshanyue@guijilingjing.com   (workspace shanyue 的 admin, role 20)
  guanshanyue@lingjing.com        (workspace test 的 admin, role 20；同时是 instance admin)
workspaces: shanyue / test
instance: guijinglingjing, is_setup_done=true, workspaces_exist=true
```

因此 `register_instance` 每次都打印 `Instance already registered`，`/god-mode/` 不再显示注册表单——**这是正常行为，不是启动失败**。

### 1.1 与 Docker 栈的能力差

| 角色 | Docker 栈 | 当前无 Docker 栈 | 影响 |
| --- | --- | --- | --- |
| PostgreSQL | `strata-db` | ✅ 私有集群 `.local\pgdata`（55432） | 无差异 |
| Redis | `strata-redis` (valkey) | ❌ 未安装 → `local_native` 降级为 LocMemCache | 多进程缓存不共享；live 应用无法启动 |
| RabbitMQ | `strata-mq` | ❌ `AMQP_URL=memory://` | 后台任务**永不执行** |
| Celery worker | `worker` | ❌ 未启动 | 邮件、Webhook、导出、集成同步全部没有消费者 |
| Celery beat | `beat-worker` | ❌ 未启动 | 定时任务（周期清理、集成轮询）不触发 |
| MinIO | `strata-minio` | ❌ `USE_MINIO=0` | 附件、头像、封面图上传不可用 |
| API | `api` | ✅ `runserver 0.0.0.0:8010` | 无差异 |
| 前端 | 宿主机 `pnpm dev` | ✅ turbo（3000/3001/3002） | 无差异 |
| live（3100） | 需要 Redis | ❌ 未启动 | 实时协作不可用 |

结论：**主流程（登录、工作区、Issue/WorkItem、看板、评论）可用；异步与文件能力不可用。** 这就是"别的软件 `docker compose up` 一下就什么都有、这里却少几块"的根本原因。

## 2. 目标

在**零容器**前提下，按优先级把上表里 ❌ 的格子补成 ✅：

1. P0 Redis 原生进程 → 恢复缓存共享，并为 Celery 提供 broker；
2. P1 Celery worker + beat → 后台任务真正执行；
3. P2 MinIO 原生进程 → 附件上传可用；
4. P3 live 应用 → 实时协作；
5. P4 运维面：`-Status` 如实报告、日志分离、`-Stop` 收干净。

不改任何业务代码；只动 `local-dev.ps1`、`.local\bin`、`apps/api/.env`。

## 3. 分阶段计划

### 第 0 步（前置）：确认兜底行为可接受

现状已是"降级但不崩"。先把这条写死：任何补齐步骤失败，脚本**必须**退回当前行为（LocMemCache + memory broker + `USE_MINIO=0`）并打印 `[warn]`，不得 `exit 1`。

### 第 1 步（P0）：原生 Redis

- 二进制放置：`.local\bin\redis-server.exe`。`Find-Tool` 已经优先查这个目录（`local-dev.ps1` 第 243-247 行），放进去即可被自动拉起，无需改脚本查找逻辑。
- 现有启动分支（第 549-565 行）已实现：`--port 6379 --dir .local\redis-data`，成功则 `$useRedis = $true`。
- 需要补的动作：
  1. 启动成功后把 `$useRedis` 传给 Django 进程：脚本已设置 `STRATA_LOCAL_REDIS=1`（第 708 行），使 `local_native` 不再覆盖 `CACHES`，直接使用 `local.py` 里指向 `REDIS_URL` 的缓存；
  2. `Start-Background` 写 `redis.pid`，`-Stop` 里已包含 `redis`（第 475 行）；
  3. `-Status` 增加一行 Redis 探测（当前 `Show-Status` 没有 Redis/MinIO）。

验收：`redis-cli ping` → `PONG`；在 API 进程里打印 `settings.CACHES["default"]["BACKEND"]` 应为 `django_redis.cache.RedisCache`（降级时是 `django.core.cache.backends.locmem.LocMemCache`）；重启 API 后会话/缓存命中数保持。

### 第 2 步（P1）：Celery worker / beat 走 Redis broker

不需要 RabbitMQ。`common.py` 第 360-366 行的逻辑是：

```python
AMQP_URL = os.environ.get("AMQP_URL")
if AMQP_URL:
    CELERY_BROKER_URL = AMQP_URL
```

当前 `.env` 写的是 `AMQP_URL="memory://"`。第 1 步成功后可改成：

```dotenv
AMQP_URL="redis://127.0.0.1:6379/0"
```

然后按容器里的同一套命令起进程（`apps/api/bin/docker-entrypoint-worker.sh` / `-beat.sh` 的语义）：

```powershell
uv run celery -A strata worker -l info -P solo
uv run celery -A strata beat   -l info
```

- Windows 上必须用 `-P solo`（默认 prefork 在 Windows 不可用）；solo 是单并发，够开发用。
- `beat` 使用 `django_celery_beat` 的 `DatabaseScheduler`（`strata/celery.py` 第 124 行），调度记录落在同一个 PostgreSQL 里。
- 脚本改动：新增 `Start-Background -Name "worker"` / `-Name "beat"`，`-Stop` 顺序补上（worker → beat → api → 前端）。任务日志写入 `.local\logs\worker.log` / `beat.log`。

验收：进后台改一个工作区名或触发一封邀请邮件，`worker.log` 出现 `Task ... succeeded`；`beat.log` 每 60s 有心跳。

### 第 3 步（P2）：原生 MinIO

- 二进制：`.local\bin\minio.exe`，脚本第 567-575 行已支持 `--address :9000 --console-address :9090`。
- 启动成功后需把 `USE_MINIO` 置 1 并确认 bucket：脚本第 694-701 行已有 `create_bucket` 调用，前提是 `$useMinio` 为真。
- `common.py` 第 337 行有个保护：`USE_MINIO=1` 且 `AWS_SECRET_ACCESS_KEY == "secret-key"` 时会报错。脚本第 592-593 行已经生成随机 `AWS_SECRET_ACCESS_KEY`，满足条件。

验收：工作区设置里上传头像/附件成功；`http://localhost:9090` 能登录 MinIO 控制台并看到 `uploads` bucket。

### 第 4 步（P3）：live 应用（可选）

`apps/live` 需要 Redis（第 1 步已具备）。届时可用 `.\local-dev.ps1 -Apps web,admin,space,live`，端口 3100。当前默认不启动它（`$AppPorts.live = 3100`，但 `-Apps` 默认值是三个）。

### 第 5 步（P4）：运维面收尾

- `Show-Status` 补 Redis / MinIO / worker / beat 四项探测，与 `$AppPorts` 一起报告。
- `-Stop` 用 pid 文件逆序关闭，pg 集群最后关。
- 日志：`api.log`、`worker.log`、`beat.log`、`frontend.log`、`postgres.log` 分开；任何 `Start-Background` 失败都要把对应 `*.err.log` 尾部打出来（`Write-LogTail` 已实现）。

## 5. 风险登记

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| Windows 版 Redis 非官方 | 官方不再发布 Windows 二进制，`redis-server.exe` 多来自社区构建 | 只监听 `127.0.0.1`，仅开发用；放 `.local\bin`，不入库（`.gitignore` 已忽略 `.local`） |
| Celery solo 单并发 | 长任务会阻塞其他任务 | 开发可接受；需要并发时再评估 `gevent`/`eventlet` |
| 端口冲突 | 9000/9090 常被其他服务占用；6379 可能已有本机 Redis | 已有分支会检测"端口已监听则复用"；冲突时可改 `$MinioPort`/`$RedisPort` |
| MinIO 凭据 | `USE_MINIO=1` + 默认 `secret-key` 会直接报错 | 脚本已生成随机密钥（第 590-593 行） |
| Redis 无持久化策略 | 默认 RDB 保存到 `.local\redis-data` | 开发环境可接受；清缓存直接删该目录 |
| 私有 PG 集群与 Docker 端口 | 55432 避开 5432，两套可共存 | 保持 55432 不变 |
