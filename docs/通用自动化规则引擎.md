# 通用自动化规则引擎 MVP

## 目标

允许项目管理员为工作项配置简单、可审计的自动化规则，减少重复的分派和属性维护操作。

## MVP 范围

- 触发器：`issue_created`、`issue_state_changed`
- 条件：工作项当前 `state_id`、`priority`（多个条件按 AND 计算）
- 动作：设置 `priority`、添加负责人、添加标签
- 管理：规则的创建、查询、修改、删除和启停
- 审计：每次匹配都记录成功、跳过或失败状态以及错误信息

不在 MVP 范围内：可视化条件编排、定时触发、跨项目动作、Webhook 动作和失败重试。

## API

路径：`/api/workspaces/{slug}/projects/{project_id}/automation-rules/`

- `GET /`：列出项目规则
- `POST /`：创建规则
- `GET /{rule_id}/`：读取规则
- `PATCH /{rule_id}/`：修改或启停规则
- `DELETE /{rule_id}/`：删除规则

示例：

```json
{
  "name": "新建紧急工作项自动分派",
  "trigger": "issue_created",
  "conditions": { "priority": "urgent" },
  "actions": { "assignee_ids": ["USER_UUID"], "label_ids": ["LABEL_UUID"] },
  "is_active": true
}
```

## 执行语义

规则在工作项成功写入后同步执行。执行器只更新白名单字段及关联表，不再次调用工作项 HTTP 接口，因此不会递归触发规则。无实际变化的动作记为 `skipped`。单条规则失败不会阻止其他规则执行，也不会回滚用户原本的工作项写入。

## 安全与约束

- 管理接口仅项目管理员可用。
- 负责人必须是当前项目的活跃 Member/Admin；标签必须属于当前项目。
- 状态条件必须引用当前项目状态。
- 所有查询同时限定 workspace、project 和对象 ID，防止跨项目引用。
- JSON 配置由序列化器按固定 schema 校验，不接受未知字段。
