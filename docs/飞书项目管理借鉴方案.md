# 飞书项目管理借鉴方案

## 1. 结论

Strata 当前的「左侧项目导航 + 中间工作项列表 + 右侧工作项详情」已经具备良好的三栏骨架。
后续应重点借鉴飞书项目的**连续处理效率、可配置视图、就地编辑和统一工作项模型**，而不是逐像素复制其界面。

建议的建设顺序：

1. 完善三栏联动和工作项详情编辑体验。
2. 将静态列表升级为可配置、可保存的多视图系统。
3. 增加批量操作、快捷键和高频任务处理能力。
4. 建立统一工作项类型、关系和自定义字段模型。
5. 在基础模型稳定后建设甘特图、自动化和跨项目报表。

## 2. 借鉴目标

本方案不以视觉相似为目标，而以降低项目管理中的操作成本为目标：

- 用户在列表中连续处理工作项时不需要频繁跳转页面。
- 项目成员可以用不同视图观察同一份工作项数据。
- 高频字段能够直接修改，减少弹窗和表单层级。
- 项目负责人可以批量整理、分派和调整工作项。
- 需求、任务、缺陷等类型共享统一模型，同时保留各自的流程和字段配置。

## 3. 当前界面的判断

当前界面已经具备以下正确基础：

- 工作区和项目导航位于左侧。
- 工作项列表和详情同时显示。
- 详情顶部展示状态、优先级、负责人和日期等核心属性。
- 详情中已经包含父项、标签、活动和评论等概念。

仍需改善的问题：

- 详情区域宽度较大，但信息密度偏低，存在大量无效留白。
- 中间区域更接近简单列表，缺少字段列、分组、筛选和批量选择。
- 核心属性主要依赖图标表达，新用户需要猜测字段含义。
- 工作项属性和活动流距离过远，信息组织不够紧凑。
- 图标按钮语义较弱，需要 Tooltip 和稳定的快捷键提示。
- 工作区导航与项目导航同时出现在左侧，层级容易混淆。

## 4. 核心设计建议

### 4.1 强化三栏联动

三栏结构应成为高效处理工作项的主要模式：

- 点击中间列表项时，右侧详情即时切换，不发生整页跳转。
- 当前工作项 ID 同步到 URL，支持刷新、复制链接和浏览器前进后退。
- 切换工作项后保留列表的筛选条件、分组方式、选中项和滚动位置。
- 允许拖动调整列表与详情宽度，并记住用户的宽度设置。
- 右侧详情支持收起、面板、全屏和独立页面四种显示方式。
- 使用方向键或快捷键切换上一条、下一条工作项。
- 当详情存在未保存内容时，切换工作项前给出明确提示。

### 4.2 将列表升级为视图系统

不同视图应共享同一份工作项数据，而不是形成相互独立的功能模块。

建议逐步支持：

| 视图 | 主要用途 |
|---|---|
| 表格 | 批量编辑、字段对比和项目盘点 |
| 看板 | 按状态、负责人、优先级等字段分组推进 |
| 树形列表 | 展示父子工作项和任务拆解关系 |
| 日历 | 查看开始日期、截止日期和里程碑 |
| 甘特图 | 查看排期、进度和依赖关系 |

每个视图都应支持：

- 筛选、排序、分组和搜索。
- 配置显示字段、字段顺序和列宽。
- 保存为命名视图，并区分个人视图与项目共享视图。
- 复制视图、固定到项目导航以及设置默认视图。
- 通过 URL 保存视图状态，便于分享和恢复。

### 4.3 重构工作项详情的信息层级

详情建议分为三个层次：

#### 顶部摘要区

- 工作项编号、类型、标题。
- 状态、优先级、负责人、开始日期和截止日期。
- 订阅、复制链接、更多操作。
- 核心字段应始终可见，并支持单击直接编辑。

#### 主体内容区

- 描述。
- 子工作项及完成进度。
- 关联、阻塞、被阻塞和重复关系。
- 附件和外部链接。
- 可折叠的其他属性与自定义字段。

#### 活动与协作区

- 将评论、字段变更、状态变更和附件操作统一到活动流。
- 支持「全部、活动、评论」筛选。
- 评论支持 `@成员`、引用、附件和富文本。
- 评论输入框固定在详情底部，避免长页面滚动后无法快速回复。

### 4.4 增加直接编辑与批量操作

高频操作不应要求打开额外弹窗：

- 在详情中直接编辑标题、状态、优先级、负责人和日期。
- 在表格中直接编辑单元格，使用 Enter、Tab 和方向键连续录入。
- 创建工作项时只要求标题，其余字段可按需补充。
- 创建后保持输入位置，支持连续创建。
- 多选工作项后批量修改状态、负责人、优先级、标签、周期和模块。
- 支持批量移动、复制、归档、删除以及转为子工作项。
- 对删除、归档和跨项目移动等操作提供清晰确认和恢复机制。

### 4.5 建立统一工作项模型

不建议为需求、任务和缺陷分别维护三套列表与详情页面。建议使用统一的 Work Item 模型，
由工作项类型控制以下内容：

- 名称、图标和颜色。
- 默认字段和必填字段。
- 状态流程及允许的状态迁移。
- 默认创建模板。
- 可用操作和权限。
- 编号前缀与展示规则。

统一模型至少需要支持以下关系：

- 父项与子项。
- 关联。
- 阻塞与被阻塞。
- 重复与被重复。
- 跨项目关联。

这样可以在不复制页面和状态逻辑的前提下，继续增加新的业务类型。

### 4.6 优化项目导航层级

建议的项目内导航结构：

```text
项目
├─ 工作项
│  ├─ 全部工作项
│  ├─ 我的工作
│  └─ 已保存视图
├─ 周期
├─ 模块
├─ 页面
└─ 项目设置
```

导航设计原则：

- 常用视图可以固定到项目导航。
- 低频能力收纳到「更多」，避免侧边栏持续增长。
- 工作区级功能和项目级功能使用清晰的分组、缩进与分隔。
- 项目切换后尽量保留用户上次访问的位置。

### 4.7 快捷键和命令菜单

建议以 `Ctrl/Cmd + K` 提供统一命令菜单，并逐步增加：

| 操作 | 建议快捷方式 |
|---|---|
| 创建工作项 | `C` |
| 编辑当前工作项 | `E` |
| 指派负责人 | `M` |
| 打开搜索或命令菜单 | `Ctrl/Cmd + K` |
| 上一条/下一条工作项 | `J` / `K` 或方向键 |
| 关闭详情 | `Esc` |

快捷键不能只存在于文档中，应同时显示在 Tooltip 和命令菜单中，并允许在输入框聚焦时自动避让。

## 5. 不建议直接照搬的部分

- 不照搬过大的详情面板，应根据字段数量提供紧凑和舒适两种密度。
- 不只用图标表示核心字段，首次使用和信息复杂时应显示字段标签。
- 不把所有能力都放进左侧导航，应以保存视图代替固定菜单堆积。
- 不为每个工作项类型复制页面、接口和状态管理逻辑。
- 不在基础数据模型稳定前优先开发甘特图和复杂报表。
- 不将飞书的组织结构、权限和术语直接映射到 Strata，应沿用现有 workspace、project、cycle、module 和 work item 语义。

## 6. 分阶段实施计划

### P0：打磨核心处理路径

- 三栏联动和详情面板模式。
- 当前工作项与 URL 同步。
- 列表状态、滚动位置和面板宽度保持。
- 核心属性就地编辑。
- 评论与变更记录统一活动流。
- 上一条、下一条和关闭详情快捷操作。

**验收目标**：用户可以在不离开列表上下文的情况下，连续查看并修改多个工作项。

### P1：建设可配置视图

- 表格视图和看板视图统一数据源。
- 筛选、排序、分组和显示字段配置。
- 个人视图与项目共享视图。
- 表格单元格编辑和工作项批量操作。
- 命令菜单与高频快捷键。

**验收目标**：用户可以针对不同角色保存工作视图，并完成常见的批量整理工作。

### P2：增强工作项模型

- 可配置工作项类型。
- 自定义字段。
- 父子关系、依赖关系和跨项目关联。
- 工作项模板。
- 类型级状态流程和权限规则。

**验收目标**：需求、任务和缺陷能够复用同一套基础能力，并按类型呈现不同流程。

### P3：规划与自动化

- 日历和甘特图。
- 跨项目「我的工作」。
- 自动分派和字段更新规则。
- 项目进度、吞吐量和逾期报表。
- 视图订阅与定期摘要。

**验收目标**：项目负责人能够进行跨周期排期、自动化维护和趋势分析。

## 7. 产品与技术约束

结合仓库现有约定，实施时应遵循：

- 业务状态放在 `apps/web/store`，可跨应用复用的状态才进入 `packages/shared-state`。
- web 专属业务 API 放在 `apps/web/services`，不要默认迁移到 `packages/services`。
- 通用复合组件与 Strata 专属组件放在 `packages/blocks`，并使用子路径导入。
- 基础组件优先使用 `@makestrata/propel` 已发布组件。
- 视图配置、列表选择和详情面板状态应拆分职责，避免形成巨型 store。
- URL 只保存可分享状态；临时交互状态（如面板宽度）保存在用户偏好中。
- 新增交互必须有单元测试，重点覆盖 URL 同步、切换保持、批量编辑和未保存内容保护。
- 批量更新接口需要明确部分失败、权限不足和并发冲突的反馈方式。

## 8. 建议的关键指标

上线后可使用以下指标判断改造是否有效：

| 指标 | 期望变化 |
|---|---|
| 从列表打开并完成一次字段修改的操作次数 | 下降 |
| 连续处理 10 个工作项所需时间 | 下降 |
| 列表与详情间整页跳转次数 | 接近 0 |
| 用户创建和复用保存视图的比例 | 上升 |
| 批量操作覆盖的工作项数量 | 上升 |
| 因切换页面导致的筛选或滚动状态丢失 | 接近 0 |
| 快捷键和命令菜单的周活跃使用率 | 稳步上升 |

## 9. 第一批需求拆分建议

第一批迭代建议控制在三项，先验证核心方向：

1. **工作项详情路由化**：列表选中项与 URL 双向同步，刷新和分享链接后可恢复详情。
2. **详情面板体验**：支持收起、全屏、宽度调整和上一条/下一条切换，并保持列表上下文。
3. **核心字段就地编辑**：标题、状态、优先级、负责人和日期直接修改，补齐加载、失败回滚和权限反馈。

完成以上三项后，再开始保存视图和批量编辑。这样可以先建立稳定的交互与状态基础，避免多个视图重复实现同一套详情逻辑。

## 10. 实施进度

> 更新于 2026-11-10。

### 已完成

- 工作项详情与 URL 双向同步。
- 刷新页面后按 URL 恢复详情。
- 浏览器前进、后退驱动详情切换。
- 打开和关闭详情时保留原有筛选、布局与分组参数。
- 侧边详情支持拖拽调整宽度。
- 面板宽度写入本地偏好，刷新后继续使用。
- 拖拽分隔线支持键盘调整，双击可恢复半屏宽度。
- 移动端继续使用全宽详情，不受桌面宽度偏好影响。

### 待完成

- 上一条、下一条工作项导航。
- 详情模式偏好持久化。
- 未保存内容切换保护。
- 评论输入区固定与活动流密度调整。
- 保存视图和批量编辑。
